QA orchestration demo

Larkspur Hollow Clinic patient intake. Fictional clinic, fake data only.

Orchestrated by Claude Code; requirement, review checkpoints and verification by Bryce Miranda.

What this is

An end-to-end QA run on a small demo app, driven by an AI coding agent from the terminal. Claude Code read a Jira story, explored the live app and wrote a test plan from it. It then generated Playwright tests, ran them against the clean app and against two deliberately injected bugs, filed the defects in Jira with evidence, and published the HTML reports with traces on this site. The story's acceptance criteria were drafted with Claude, then reviewed and approved by Bryce Miranda. Bryce reviewed the plan, the bug drafts and the pull request at three checkpoints before anything was posted to Jira or merged. Along the way the tests also found a real bug that nobody planted (see What the tests found).

Pipeline

  4. Runsclean · allergy · dob
  5. Healclean app only, not needed

CLI tools, no MCP servers: every step is a shell command you can read in the log and rerun, and the same commands could run in CI without an AI agent.

Why TypeScript: the installed playwright-cli skill's plan / generate / heal workflow targets @playwright/test and emits TypeScript; Python attach support (pytest --playwright-debug=cli) shipped in Aug 2026 but isn't in the bundled skill yet.

The repo's existing Python Selenium and pytest-playwright suites are unchanged. This TypeScript suite sits next to them in e2e/.

What the tests found

PIQ-4: "today" is computed in UTC. While exploring the date-of-birth boundary for AC2 and AC3, the agent noticed that docs/app.js line 65 compares the entered date with new Date().toISOString(), which is the UTC date, not the user's local date. This bug is not one of the toggles. It is in the normal app.

  • Ahead of UTC: in Pacific/Kiritimati (UTC+14) at 02:00, a newborn registered on its birth day is rejected as "in the future".
  • Behind UTC: in America/New_York after 20:00 EDT (19:00 EST), tomorrow's date is accepted and saved.
  • Each case failed 3 of 3 times with a pinned clock. The control (19:30 EDT) behaved correctly 3 of 3 times.

Two tests cover it, found-utc-today.spec.ts, marked test.fail() with a link to PIQ-4. That keeps the clean run green, and once the bug is fixed Playwright reports "expected to fail, but passed". This was checked against a scratch copy of the app with line 65 changed to the local date: both tests flagged as expected. The real app was not changed.

Also seen, but outside the story's wording and not filed: impossible dates such as 2026-02-30 are accepted.

What the AI got wrong, and how it was caught

Claude Code's own mistakes

  • The bug-filing script grabbed the wrong Jira key. It read the new key from the first "PIQ-n" in acli's create output, which echoes the description and its mention of PIQ-1. Caught by the script's own read-back ("Story, wanted Bug") and Jira refusing to link PIQ-1 to itself. PIQ-1 was not changed. Fixed by looking the bug up by its exact summary.
  • A "no writes" check wrote to Jira. Rerunning the script to show it was idempotent posted a duplicate comment on PIQ-1, because acli's link-list JSON leaves out the linked key, so the "already linked" check failed. Caught by listing the comments. The duplicate was deleted with Bryce's approval, the script now reads links from the issue itself, and reruns are checked with DRY_RUN=1 first.
  • Wrong Node version, twice. playwright-cli was first installed under Node 16 because nvm's old default was still on PATH, and one later command ran without switching. Both caught by running the command and reading the error.
  • pause-at on a helper line didn't pause the debug run. It only stops on Playwright API calls. Caught because the session ended with nothing explored.
  • A claim logged before it was run (a hidden error element keeps its old text), based on reading the code. It was then verified in the browser before moving on.
  • Suggested link type rejected: the agent proposed "Blocks". Bryce chose "Relates", because the clean app meets every AC and the defects only exist with a toggle on.

Corrections to the brief and the tool docs, caught by checking

  • The brief said acli jira workitem comment-create. In acli 1.3.39 that command doesn't exist; it's acli jira workitem comment create, found from --help.
  • The brief said "after 20:00" in New York. That's true under EDT. Under EST (winter) the window starts at 19:00.
  • The brief cited Playwright issue #38610 as an open request for Python test agents. It was closed as completed in Aug 2026; TypeScript was kept because the installed skill doesn't cover Python yet.
  • The playwright-cli skill docs: after attach, commands need -s=<session>; "resume, then explore" closes the browser (pause-at works); the CLI's getByTestId ignores the project's data-test-id setting. The skill also suggests test.fixme for confirmed bugs, which this run's rules forbid.
  • acli's own --help: the comment delete example uses --issue but the flag is --key. Priority isn't a flag, but additionalAttributes in --from-json sets it.
